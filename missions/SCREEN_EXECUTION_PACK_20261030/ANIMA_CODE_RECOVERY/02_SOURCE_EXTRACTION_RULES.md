# Source code extraction rules

- A photographed code line is only a transcription candidate; screenshots cannot preserve all hidden source file paths, exact characters, non-visible code or binary assets.
- Do NOT run OCR-generated TypeScript as a native provider without syntax checking and human semantic verification.
- Do NOT assert 86 screenshots = 86 files: one long capture may contain a partial file and screenshots may overlap.
- Never infer a completed Windows API from a generic `NOT_CONNECTED` handler, mock or a changelog.
- Need the exact Anima source ZIP to make a complete machine-readable and buildable code recovery.
- Screenshots 001, 002, 005 and 079 visually confirmed index.html, Windows applications inventory, Windows files provider and changelog instructions respectively; these claims are evidence of CODE APPEARING IN IMAGES, not tested behavior.
- Duplicate pairs proven by SHA-256: Capture 064 == 065 and Capture 072 == 073. Save only one physical copy per unique PNG.
- Categorization in the recovery ZIP is approximate: Bootstrap, Electron Native, UI/hooks, domain contracts/services, React UI/screens, project notes. Original file paths must be verified from real export.
- Do not modify, stage, commit or push canonical source or owner evidence as part of recovery and review.
