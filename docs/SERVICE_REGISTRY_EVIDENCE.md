## Rules for updating

1. Read the service's actual bridge, UI and controlled fixture test before changing a status.
2. An action service is not complete until a disposable-fixture effect test proves the after-state and the user approval gate is tested (positive and negative).
3. Never mark `IMPLEMENTED_AND_TESTED` for a plan, preview, toast or color badge.
4. Live account/OS/file changes are always separate user-consent gates.
5. Keep the row's missing-dependency list precise; do not use generic "not implemented" when a specific provider or approval is missing.
